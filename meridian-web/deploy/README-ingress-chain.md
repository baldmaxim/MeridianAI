# Цепочка ingress и лимит тела запроса

Домен приложения может смотреть **не напрямую** на портальный ingress, а на внешний
реверс-прокси (например, релей с «разрешённым» IP, через который приложение доступно там,
где прямой доступ к хостингу или к S3 закрыт). Тогда запрос проходит:

```
браузер → внешний реверс-прокси (домен резолвится сюда)
        → infra-nginx портала (deploy/infra-nginx/conf.d/meridian.conf)
        → api / frontend / S3
```

## Правило

`client_max_body_size` должен быть поднят **на каждом** прокси в цепочке. Достаточно одного
звена со значением по умолчанию (или с общим лимитом на `/`), чтобы загрузка падала с **413**,
и на портальном ingress этого не будет видно вообще.

Признак, по которому определяется виновник: заголовок `Server` в ответе 413 — версия и сборка
nginx у каждого звена своя (например `nginx/1.27` у портального ingress в Docker против
`nginx/1.24.0 (Ubuntu)` у хостового прокси).

## Что было (инцидент)

После перевода presigned-ссылок на свой домен (`S3_PUBLIC_BASE_URL` → `https://<домен>/s3`)
загрузки в хранилище перестали проходить: на портальном ingress `location /s3/` имел
`client_max_body_size 1024M`, но на внешнем реверс-прокси в server-блоке домена стоял общий
`client_max_body_size 25M`. Всё до 25 МБ проходило, больше — 413. Прямой PUT в S3 в обход
домена работал. Диагностику осложняло `access_log off` на `/s3/` — 413 не попадал ни в один лог.

Исправление: на внешнем прокси добавлен отдельный `location /s3/` с тем же лимитом, что и на
портальном ingress, плюс `proxy_request_buffering off` (иначе прокси копит всё тело на своём
диске) и увеличенные таймауты.

## Чек-лист при переносе домена или добавлении прокси

1. `dig +short <домен>` — убедиться, куда реально резолвится домен.
2. На каждом звене: `location /s3/` с `client_max_body_size` не меньше `STASH_MAX_UPLOAD_MB`.
3. `proxy_request_buffering off` и `proxy_buffering off` на всех звеньях — иначе крупный файл
   буферизуется на диск промежуточного узла, а `Range` для плеера ломается.
4. `proxy_read_timeout` / `proxy_send_timeout` с запасом (600s).
5. Проверка: presigned PUT ~250 МБ через домен → 200; тот же presigned напрямую в S3 → 200.
6. `S3_PUBLIC_BASE_URL` должен быть задан в env портала — иначе presigned-ссылки уйдут прямо
   на S3 в обход домена (см. `portal/meridian.env.example`).
