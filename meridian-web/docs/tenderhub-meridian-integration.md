# Интеграция TenderHub с Meridian

TenderHub ведёт перечень тендеров и расчёты. Meridian хранит карточки объектов, готовит контекст встреч и связывает найденные сведения с источниками. Рабочие файлы остаются в сетевых папках. PayHub подключается через существующий `payhub_project_id` для поиска официальной переписки.

## 1. Загрузить действующие тендеры из рабочего перечня

1. Скачать полный JSON-ответ `GET /api/v1/tender-registry/export` (`{"data": [...]}`) с машины, на которой есть машинный ключ TenderHub с правом `registry:read` на весь реестр. Выгрузка включает тендеры, для которых ещё нет расчёта. `GET /api/v1/tenders/brief` отдаёт карточки расчётов и их версии. В PowerShell сохранять ответ через `Invoke-WebRequest -OutFile`, чтобы сохранить исходные байты UTF-8. Импортёр получает готовый файл.
2. Импортировать статусы «В расчёте», «Направлено» и «Ожидание ПД». Архивные строки видны в отчёте. При изменении состояния уже связанной строки обновляется статус TenderHub в связи. Карточку Meridian можно продолжать использовать для встреч и документов.
3. Сохранять UUID строки TenderHub отдельно от ID объекта Meridian и номера тендера. Несколько строк реестра могут относиться к одному объекту. При совпадении названий или номеров сверить заказчика, адрес и пакет работ. Существующую карточку указать явно. Для нескольких строк одного нового объекта создать одну карточку и указать её ID для этих строк. Строки без номера тоже допускают ручную привязку.
4. Сверить отчёт предварительного запуска с количеством записей в трёх рабочих вкладках. Проверить кандидатов по заказчику, адресу и пакету работ. В список создания включить только подтверждённые UUID. Для существующих карточек подготовить явные привязки.

### Команды импорта

Запускать из `meridian-web/backend` либо из каталога приложения в контейнере Meridian с его рабочим окружением. На целевой базе должна быть применена миграция `0038`. Снимок и отчёт содержат рабочие данные. Хранить их в закрытом рабочем каталоге.

```bash
python -m app.tools.import_tenderhub_registry /path/registry.json
python -m app.tools.import_tenderhub_registry /path/registry.json --create-list /path/create-list.json --links /path/links.json
python -m app.tools.import_tenderhub_registry /path/registry.json --create-list /path/create-list.json --links /path/links.json --apply --owner-user-id <meridian-user-id>
```

`links.json` сопоставляет UUID строки TenderHub с числовым ID существующего объекта Meridian.

```json
{"00000000-0000-0000-0000-000000000001": 123}
```

`create-list.json` содержит только UUID, по которым подтверждено создание объекта.

```json
["00000000-0000-0000-0000-000000000002"]
```

Предварительный запуск использует транзакцию только на чтение. Без `--create-list` он показывает кандидатов на создание. Перед применением нужно повторить сверку с теми же файлами `--create-list` и `--links`. `--apply` создаёт карточки только для UUID из списка, прошедших проверку совпадений. Строки `review_create` ждут решения. Если готовых привязок нет, аргумент `--links` можно опустить.

При повторном запуске по тому же UUID обновляются сведения в связи. Импорт применяет разрешённые строки одной транзакцией. Имена, заметки и связи с PayHub существующих карточек редактируются в Meridian. Для отмены конкретного импорта использовать IDs из отчёта и проверять созданные после импорта встречи и документы перед изменением карточек.

## 2. Подключить расчёты и обновление реестра

1. Подключить повторное получение полного реестра через `tender-registry/export` с правом `registry:read`. Учитывать исчезнувшие записи только после успешного получения полного списка. Передавать в Meridian поля, нужные карточке и сопоставлению.
2. Взять `tenders/brief` и `tenders/{id}/overview` с `tenders:read`. Сопоставлять по номеру в качестве кандидата, а в Meridian хранить подтверждённый UUID карточки расчёта и её версию. При нескольких расчётах показывать лот или пакет, версию и дату. При явной связи в TenderHub использовать её.
3. Вывести в Meridian номер, статус и ссылку на тендер, а также дату последнего обновления. Для переговоров отдавать утверждённые коммерческие показатели и выбранные разделы через `positions/with-costs` с указанием версии, валюты и основания суммы, когда эти сведения доступны. Суммы определяет TenderHub. Проверить, что расчёт попадает в контекст встречи только при выборе соответствующего тендера или лота.

## 3. Подключить слепок шары

1. Считать перечень папок и файлов на машине внутри сети, используя доступ на чтение. Сопоставить папки с номерами тендеров. Сохранять подтверждённую папку, относительный путь файла, размер и дату изменения. Пока папка не подтверждена, объект остаётся доступным с отметкой о состоянии привязки.
2. Выбрать актуальные ТЗ, КП, ВОР, договор и протокол разногласий. Для выбранных файлов считать SHA-256 и загружать изменившиеся версии через существующий механизм Meridian. Связать документ с исходным путём и конкретным тендером, если он относится к одному лоту. Общие документы привязывать к объекту. После готовности новой версии заменять рабочую версию в контексте.
3. Проверить права на каждом источнике. В текущем Meridian объекты и документы общие для авторизованных сотрудников. Файлы и расчёты с ограниченным доступом подключать после реализации соответствующих прав в Meridian. Проверить поиск по документам, ссылку на источник и отсутствие материалов соседнего лота в контексте встречи.

## 4. Выпуск и массовый импорт

1. Пройти проверки, собрать образ Meridian в CI и выпустить через штатный GHCR-деплой. Проверить миграцию `0038` и готовность API.
2. Получить актуальный снимок TenderHub и выполнить предварительный запуск на целевой базе. Сопоставить проблемные строки, сохранить отчёт и применить импорт.
3. Повторить предварительный запуск с тем же снимком. Проверить, что ранее применённые строки предлагают `refresh`, а все действующие тендеры имеют связи. Сверить карточки и выбор объекта при создании встречи в Meridian.
